# Literature and Artifact Audit — 2026-09-28

## Scope and method

This targeted update covers papers submitted from 2026-08-14 through 2026-09-28, plus release-status changes for entries already in the registry. Searches covered arXiv robotics, vision, and learning terms for reward/value/progress/verifier and recent benchmark work; candidates were checked against original arXiv pages, author pages, official GitHub repositories, and official Hugging Face model/dataset cards. It is a living literature sweep, not a claim that every arXiv cross-list was exhaustively screened. Dates below refer to first submissions, not discovery dates. All new methods remain labeled as preprints unless an official proceedings source was verified.

The project anchor's semantics-first scope remains in force: a policy with reward feedback is not automatically a reward model. We record a task-conditioned evaluator's native output, evidence, and role separately from its policy/world-model coupling. Paper, code, weights, data, and licenses are audited independently.

## New core records in `registry/papers.yaml`

| First submission | Record | Native signal and boundary |
|---|---|---|
| 2026-08-19 | [Dream2Reward](https://arxiv.org/abs/2608.18787) | A signed local transition reward compares observed latent change to the predicted direction/magnitude of successful change. Positive-only robot demonstrations train the predictor; the reward can penalize wrong or stagnant transitions. It is not an absolute success probability. |
| 2026-09-06 | [VLA-Corrector, Song et al.](https://arxiv.org/abs/2609.06508) | A separate learned verifier consumes observation, proprioception, and executed-action history, infers progress/risk, and triggers stage-aware prompt recovery. Its reported policy-recovery results do not by themselves calibrate the verifier as a general reward. This September paper is distinct from Pan et al.'s [July VLA-Corrector](https://arxiv.org/abs/2607.01804). |
| 2026-09-17 | [AnyviewMeter](https://arxiv.org/abs/2609.20106) | Robometer adaptation for task-specific scalar progress uses calibrated camera rays and synchronized-view attention. The paper's real-robot tests score recorded demonstrations offline; policy improvement has not yet been evaluated. |
| 2026-09-18 | [SeeQ](https://arxiv.org/abs/2609.22085) | A PaliGemma-based subtask Q-function predicts the active subtask and scores candidate bimanual action chunks. The released checkpoint is pretrained on RoboCOIN; the paper fine-tunes on target tasks, so its values should not be presented as zero-shot calibrated success probabilities. |
| 2026-09-22 | [HiRE](https://arxiv.org/abs/2609.27068) | Hindsight edits rewards from foundation representations with successful/failed robot rollouts to penalize “trap” states for policy fine-tuning. It is an outcome-conditioned reward construction, not a separately trained universal evaluator or causal online verifier. arXiv comments identify CoRL 2026; proceedings were not checked. |

## Benchmarks and useful boundary work

- [RoboRMBench](https://arxiv.org/abs/2609.05401) tests whether **the same trajectory** receives consistent 1–5 reward judgments under semantically equivalent task paraphrases. The paper reports 2,390 real-robot trajectories and 21,673 filtered paraphrases, with Score Crossing Rate, Flip Rate, and Mean Error. It is derived from RoboRewardBench, so parent-episode overlap matters when evaluating RoboReward-family models. A reusable benchmark file release was not verified.
- [HumanTracker / HumanScore](https://arxiv.org/abs/2608.13555) is a specialist humanoid motion-tracking preference evaluator. The [official code and HumanScore checkpoint](https://github.com/GalaxyGeneralRobotics/HumanTracker) and [data repository](https://huggingface.co/datasets/GalaxyGeneralRobotics/HumanTracker) are available under their stated Apache-2.0 terms. The public dataset card lists **6,000 preference pairs and 2,500 test motion references**, a subset of the larger corpus discussed in the paper. It does not provide general instruction-conditioned task-completion labels. Its benchmark record is tagged `model_native` and specialist.
- [No Free Checker](https://arxiv.org/abs/2609.09250) is a related September survey with a broader policy-verifier scope that includes human and formal checkers; it is listed in the related-surveys section, not counted as a method. [Intrinsic Robot Rewarding](https://arxiv.org/abs/2609.17115) is listed as a position paper: the proposed frozen-VLA outcome scorer has not been shown to drive validated physical policy improvement.
- [RoboRecover](https://arxiv.org/abs/2609.28952) supplies simulated deviation-state policy-recovery scenarios, not direct reward-model quality labels; it remains adjacent. [IMPLIED](https://arxiv.org/abs/2609.13982) studies feedback implication in human-robot collaboration without a foundation-model-era trajectory evaluator. [Facet-0](https://arxiv.org/abs/2609.01596) uses an internal action-wrench critic but lacks an independently characterized evaluator in the accessible source. These screening decisions are logged in `screened_out`.

## Artifact changes for existing records

- **DenseReward:** the author [project page](https://dense-reward.github.io/) now links a real [dataset](https://huggingface.co/datasets/densereward/DenseReward) and [one-frame](https://huggingface.co/densereward/densereward-1frame) and [three-frame](https://huggingface.co/densereward/densereward-3frame-thinking) model pages; the three-frame page exposes safetensors shards. The [linked GitHub repository](https://github.com/dense-reward/dense-reward) is still empty. Weight/data cards identify Apache-2.0; no code license can be inferred from the empty repository. Its adapter remains blocked pending runnable method code and preprocessing verification.
- **RynnValue:** both [4B](https://huggingface.co/Alibaba-DAMO-Academy/RynnValue-4B/tree/main) and [8B](https://huggingface.co/Alibaba-DAMO-Academy/RynnValue-8B/tree/main) official model repositories now expose safetensors shards and Apache-2.0 model cards. The [GitHub README](https://github.com/alibaba-damo-academy/RynnValue) still says checkpoint release is in progress; the direct file listing supports updating `weights` to `available`. Upstream training datasets retain their own terms.

## Implications for RRM-Bench

1. Add a controlled **instruction-paraphrase robustness** probe with fixed source trajectories, human-checked semantic equivalence, and episode-grouped splitting. Report category-crossing and flip rates alongside reward accuracy; score invariance alone cannot establish correct judgment.
2. Separate SeeQ's **candidate-action Q ranking**, Dream2Reward's **transition feedback**, and VLA-Corrector's **recovery trigger** from absolute progress and terminal outcome scoring. Mark unsupported capability queries `N/A`.
3. Test camera sufficiency explicitly. AnyviewMeter's results motivate fixed multiview and geometry profiles, but its offline reward accuracy does not establish improved policy learning.
4. Keep HumanScore a specialized motion-quality baseline and RoboRecover a policy recovery stress source; neither substitutes for the real-robot gold track's outcome, failure-onset, PONR, and recovery re-entry labels.

## Unresolved items

- No usable official method code or weights were verified for Dream2Reward, AnyviewMeter, VLA-Corrector (Song et al.), or HiRE.
- SeeQ's pretrained weights are available under Gemma terms, but method-specific source code and the downstream fine-tuned checkpoints were not verified.
- RoboRMBench's paraphrase files and split manifests were not verified as released; paper metrics cannot yet be treated as a reproducible open benchmark.
- DenseReward's empty code repository and the split/license provenance of individual upstream real-robot data require follow-up before a runnable adapter.
