# Literature and Artifact Audit — 2026-08-13

## Scope

This update covers new and newly surfaced robotic reward/value/verifier work since the 2026-08-02 audit. The search included the complete recent `cs.RO` listing through 2026-08-13, relevant cross-lists from `cs.AI`, `cs.LG`, and `cs.CV`, exact-title searches, and official paper, project, repository, and model/data pages.

The registry keeps a strict technical boundary: a core record must evaluate robot-relevant observations, states, transitions, clips, trajectories, or an equivalent executed-behavior representation and expose a task-conditioned reward, value, progress, preference, success, failure, or verifier output. First arXiv submission dates are recorded separately from the date a paper appeared in a cross-list or was discovered by this audit.

## Result

Six core records were added to `registry/papers.yaml`:

- **RynnValue** predicts language-conditioned absolute temporal distance to completion and signed relative temporal displacement. It turns physical-seconds cost-to-go into potential-based dense reward and also emits task-match/success verification.
- **TrustRoboReward** unifies pointwise trajectory progress, pointwise grounded-video-QA answer quality, and their pairwise counterparts. POISE uses pairwise order constraints to edit inconsistent pointwise labels.
- **GORDON** learns object-centric scene-graph goal distance from action-free videos and uses temporal reward profiles to discover long-horizon stages automatically.
- **WCM** is a history-aware VLA critic that jointly estimates task value and predicts future latent state, explicitly targeting partial observability in on- and off-policy reinforcement learning.
- **Thea** exposes “Evaluation as Exit Codes”: an independent evaluator maps current synchronized physical evidence plus a tool post-condition to in-progress, success, or failure for termination, retry, recovery, and state-update gating.
- **Early Warning Signals for OpenVLA Failure under Visual Distribution Shift** trains a post-hoc linear monitor on frozen policy activations to predict failure within a 15-step horizon. It was submitted on 2026-06-29 but newly surfaced in the current `cs.RO` cross-list sweep.

WCM was submitted on 2026-07-31 and is a retrospective omission from the prior audit rather than an August paper.

## Artifact audit

- **RynnValue:** the official repository is runnable and Apache-2.0 licensed. It links 4B/8B model pages, but the same README still says checkpoint release is in progress, so weights are marked for recheck rather than fully released. No unified training-corpus release was inferred from the upstream source datasets.
- **TrustRoboReward:** an official repository contains POISE, inference, and evaluation material, but no reusable license, public model weights, or public dataset release was verified.
- **GORDON:** the author project page is live; code, weights, reusable data, and licenses were not verified.
- **WCM:** the MIT-licensed repository includes training, evaluation, and value-curve tooling. An example real-robot pick-and-place dataset and checkpoint are linked, while the repository says the remaining paper checkpoints and RL code will be released gradually.
- **Thea:** the public Apache-2.0 preview includes the evaluator interface and robot/simulation integration boundaries. The paper's evaluator model is an external upstream model rather than released method-specific weights, and the 90-checkpoint evaluator test was not found as a reusable dataset.
- **OpenVLA failure warning:** no official code, weights, or rollout dataset was verified.

Paper, code, weights, data, and license status remain separate fields; a repository or model-page link is not treated as proof of a complete reproducible release.

## Taxonomy decisions

1. **RynnValue** is `temporal_value`, not normalized `absolute_progress`: its native quantity is remaining physical time and its local counterpart is signed temporal displacement. Execution speed and completion-cutoff semantics are therefore part of the target.
2. **GORDON** is `absolute_progress` because its native dense reward is current-to-goal distance in an object-centric latent space. Its temporal reward profile and automatic stage discovery remain explicit secondary tags rather than changing the reward's meaning.
3. **WCM** is `temporal_value` with `value_world_model` coupling. Joint latent prediction is an architectural training objective, not a new reward meaning; its critic remains policy- and task-dependent rather than a universal evaluator.
4. **TrustRoboReward** is `hybrid_verifier`. Pointwise score error, pairwise preference accuracy, grounded-video-QA quality, and cross-interface consistency are kept as non-equivalent native outputs.
5. **Thea** is `hybrid_verifier`. A structured post-execution judgment that directly controls termination, retry, and recovery satisfies the project's verifier scope even though it is implemented as a harness module rather than a scalar learned reward head.
6. **OpenVLA failure warning** is `outcome` with `policy_internal` coupling. The monitor's near-term failure probability is queryable, but the evidence is intentionally narrow: the paper does not establish causal mechanism, task-held-out transfer, or a deployed recovery loop.

## Screened but not added to the core registry

- **Agentic Harnesses: LLM-Driven Verification Layers for Robot Autonomy** is retained as adjacent context. It evaluates proposed natural-language plans for feasibility, safety, ethics, and security before execution, not observed robot behavior or a trajectory reward/value signal.
- **Adaptation of Generalist Robot Policies with Minimal Data (MiDAS)** uses value-based online RL as a policy-adaptation ingredient; it does not independently characterize a transferable evaluator.
- **A Framework for Designing Reward Functions** is a general formal reward-design workflow without robot-behavior validation or a robotic reward-model artifact.
- **Synchronizing Beliefs with Second-Order Theory-of-Mind in Human-Autonomy Teams** studies preference-teaching curricula in simulation without an evaluated robot-behavior reward/verifier interface.
- New world/action models, policies, and policy-evaluation infrastructure without an explicit behavior-evaluation output remain outside the core tables.

## Benchmark implications

- The **TrustRoboReward multi-paradigm benchmark** is added as a model-native, paper-associated test: 7,030 human-annotated items across four interfaces. Its data and weights were not verified as public releases, and its paper-defined combined Overall average is not adopted as a universal project score.
- Cross-interface consistency is now an explicit benchmark capability. Report score-pair reversals and order-constraint violations alongside each interface's native metric rather than hiding them inside one average.
- RynnValue evaluates on the existing RBM-EVAL protocol, so no duplicate benchmark record was created. Temporal distance must still be tested against speed variation, cutoff errors, reversal, failure, and retry shortcuts.
- Thea's 90 balanced real-robot checkpoints provide useful model-native evidence but are not added as a reusable benchmark because no public split/data artifact was verified. Harmful false-success errors motivate an explicit evidence/calibration axis and an `unknown` option in future evaluator protocols.
- Downstream policy gains for RynnValue, GORDON, and WCM remain separate from evaluator-quality evidence.

The README project title was also restored to the canonical *Robotic Reward Models: A Taxonomy, Unified Benchmark, and Open Infrastructure*.
