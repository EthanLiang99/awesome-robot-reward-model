# Literature and Artifact Audit — 2026-07-24

## Scope

This update checked papers released after the 2026-07-19 audit and ran a backward omission sweep over robot reward models, progress/value heads, test-time action verifiers, world-model rewards, and recovery interfaces. Claims were checked against original papers, author project pages, official repositories, and model/data cards.

## Result

No new general-purpose robot reward model was found in the five-day increment after 2026-07-19. The newest relevant paper is **EgoRecovery** (2026-07-22), which contributes recovery-state boundaries and a learned recovery gate rather than a general reward model.

Twelve records were added to `registry/papers.yaml`:

### Direct reward/value models

- **Success Visitation Matching** learns a dense state-action process reward by discriminating successful from unsuccessful visitation. Its semantics are successful-support membership, not normalized task percentage.
- **Hume** adds a policy-internal value-query head for state-action value and System-2 best-of-N action selection.
- **ProgressVLA** combines an inverse-dynamics world model with a progress estimator to guide diffusion action tokens.
- **EVOLVE-VLA** uses a learned visual progress estimator as smoothed test-time reward and termination feedback.
- **ReWorld** trains a hierarchical four-dimensional reward model for physical realism, task completion, embodiment plausibility, and visual quality of robot world-model videos.
- **I-FailSense** exposes a task-conditioned failure detector through internal VLM classification heads, with emphasis on semantic instruction–execution misalignment.

### Action-conditioned test-time verifiers

- **RoboMonkey** ranks sampled or perturbed actions using synthetic preferences derived from expert-action distance.
- **RoVer** scores candidate actions and predicts a 6D direction for action refinement.
- **CoVer-VLA** learns contrastive instruction–action alignment at 20M-sample scale.
- **TapSampling** predicts task-progress outcomes for candidate action chunks and uses an Action-VAE to sample candidates.

These four systems share an inference pattern but not a reward meaning. Expert-action proximity, semantic alignment, predicted short-term progress, and final outcome must remain separate benchmark targets.

### Recovery and adjacent interfaces

- **EgoRecovery** uses human egocentric recovery clips plus small robot anchor sets to learn recovery timing and corrective intent. It supplies unusually useful recovery-to-normal boundaries for re-entry evaluation, but human motions are not robot action-token labels.
- **VERITAS** uses a gradient-free visual-trace verifier for inference-time steering and verified-rollout reuse. It is catalogued as an adjacent interface because the verifier is not a learned standalone reward model.

### Screened but not added to the core

- **FAR** is retained as adjacent retry/recovery work; its failure-contrastive adaptation is not a separately characterized reward model.
- **RoboTracer** uses process rewards inside a reasoning/training pipeline rather than exposing a reusable trajectory evaluator.
- **LifeLong-RFT** uses a multi-term VLA post-training reward rule without a separately queryable, independently benchmarked robot reward model.

## Taxonomy decisions

1. Action-conditioned test-time verification is an **architecture/use cross-axis**, not a sixth reward-semantics category.
2. Candidate-action verifiers are placed under `relative_preference` when their main interface ranks alternatives, while their training target remains explicit in secondary tags.
3. Success Visitation Matching is recorded as `hybrid_verifier`: it measures outcome-conditioned state-action support rather than guaranteed monotone progress.
4. Hume is `temporal_value` with `policy_internal` coupling.
5. ProgressVLA is `absolute_progress` with `compositional_world_value` coupling and must not be confused with **ProgVLA**.
6. EgoRecovery remains a `data_resource` / adjacent recovery interface, not a general reward model.
7. VERITAS remains `adjacent_interface` because its visual verifier is programmatic and gradient-free rather than a learned reusable RM.

## Benchmark implications

RRM-Bench should add a candidate-action verification slice with one fixed candidate set and independent physical or simulator outcomes. The benchmark should report top-1 regret, ranking quality, selected-action success, and oracle-gap closure. Hard cases should deliberately make expert-action distance, language alignment, immediate visual progress, and final task success disagree.

EgoRecovery also strengthens the case for explicit recovery re-entry labels: `failure start`, `recovery needed`, `correction interval`, and `normal-trajectory re-entry` should not be collapsed into one binary recovery label.
