# Literature and Data Audit — 2026-07-19

## Scope

Audited robot embodiments, concrete failure mechanisms, label granularity, dataset overlap, failure synthesis, and reward-model benchmark coverage for Robometer/RBM-1M, Robo-Dopamine, RoboChallenge Table30 V2, REASSEMBLE, Guardian/FailCoT, RoboArena, RH20T, Dream2Fix, and recent reward/value benchmarks.

## Added

- Added a [human-readable robot/data/failure matrix](../robot-data-matrix.md).
- Added [`registry/robot_datasets.yaml`](../../registry/robot_datasets.yaml) with source-specific count units and failure-provenance tags.
- Split Guardian into RLBench-Fail, BridgeDataV2-Fail, and UR5-Fail because their physical reality and failure-generation mechanisms differ.
- Expanded Robometer's failure-bearing sources: RoboArena, SOAR, AutoEval, Fino-Net/FAILURE, FAILSafe, RACER, LIBERO failures, and RoboReward counterfactual negatives.
- Recorded seven RH20T arm/gripper configurations and its `0/1/2–9` completion-rating semantics.
- Recorded REASSEMBLE's 4,551 demonstrations, 4,035 successes, 516 derived unsuccessful demonstrations, segment-level success, and observed assembly/disassembly failure mechanisms.
- Added `arena_scored` as a distinct supervision source and promoted RoboChallenge/RoboArena from generic evaluation resources to a dedicated arena/challenge axis.
- Recorded Table30's human-defined stage points, critical-stage success rule, retry penalties, real rollout scores/videos/logs, and V2 task-level `scoring` metadata.
- Added a [counterfactual failure-synthesis audit](../failure-synthesis-pipelines.md) covering Dream2Fix, DenseReward, semantic/temporal pseudo-negatives, and real-failure anchors.
- Added `world_model_synth` provenance and a structured Dream2Fix record with four intervention types, verifier stack, paired corrections, real evaluation embodiment, and release caveats.
- Added [robot reward-model benchmarks](../reward-model-benchmarks.md) as a first-class README category and [`registry/benchmarks.yaml`](../../registry/benchmarks.yaml) as its structured inventory.
- Audited RoboRewardBench, RBM-EVAL, RoboPulse, Suboptimal-Value-Bench, DenseReward's model-native suite, RoboProcessBench, and FailCoT/UR5-Fail by scale, labels, metrics, provenance, release state, and missing capabilities.
- Added a two-track RRM-Bench blueprint: open reproducible adapters plus a private, multi-institution real-robot gold test covering outcome, ordering, onset, recoverability, recovery re-entry, robustness, and reward-hacking probes.

## Key decisions

1. `real_executed`, `sim_executed`, `counterfactual`, `weak_auto`, `expert_only`, `arena_scored`, and `evaluation_only` remain separate training strata.
2. Robometer and Robo-Dopamine share AgiBotWorld, DROID, and LIBERO only at the known parent-source level; exact split/episode intersection is not claimed.
3. Robo-Dopamine temporal reversal is process supervision, not an observed robot failure corpus.
4. RoboArena's 9,589 physical policy episodes are not equated with Robometer's 12,379 video–language annotations.
5. Guardian collection UI item counts are not equated with its paper's canonical planning/execution supervision counts.
6. The AgiBot embodiment conflict is preserved: the original dataset and Robometer identify G1, while Robo-Dopamine's table reports A2D.
7. Table30's task/stage scoring rubric is reward-ready supervision, but it is not described as per-frame demonstration annotation without released temporal boundaries.
8. Dream2Fix-style videos retain real source context but remain generated counterfactuals; generator and verifier metadata must be retained, and held-out real failures remain the external test standard.
9. Direct reward tests, diagnostic capability tests, model-native suites, and downstream policy arenas remain distinct benchmark types.
10. The proposed RRM-Bench reports an evaluation profile rather than one overall score; policy usefulness is a separate track, not a replacement for evaluator calibration and error analysis.
11. Suboptimal-Value-Bench is catalogued from the paper/project, but its linked data repository remained empty and the WVM code repository still said “coming soon” on 2026-07-19.
