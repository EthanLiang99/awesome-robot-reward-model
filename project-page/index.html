    A clock beats every evaluator on VOC

    A control that reads only elapsed time tops the standard progress metric, yet never detects a fall. Where task state and time diverge, 17 of 26 evaluators follow time.

    Evidence 24 / 26

    No evaluator says “I can't see”

    Hiding the decisive view lowers Macro-F1 for 24 of 26 evaluators, and no evaluated interface can report that its evidence is insufficient.

    Six directions from the gaps above

    1. Learning from real failuresSigned targets and cause labels, so credit can fall.
    2. Task structure beyond the instructionCheck the constraints that motion does not reveal.
    3. Query designPair-query recall with Sequence-query precision.
    4. Evidence sufficiency and abstentionAbstain or widen uncertainty without the decisive view.
    5. Measuring what mattersTest credit withdrawal apart from chronology.
    6. From evaluators to decisionsMatch fidelity to the optimization pressure of the decision.

    06 / Toolbox

    RRM-Hub

    Adapters keep each reward model's native inputs and outputs, so existing models run on new robot videos and new evaluators are tested on the same capabilities.

    import rewardbox

rm  = rewardbox.create_reward("robometer-4b")
out = rm("robot.mp4", "open the drawer")

out.progress        # native scale, never rescaled
out.frame_indices   # source frame of each value
out.success         # models that output it
    $ pip install -e .
$ rewardbox list                  # 35 configurations
$ rewardbox doctor robometer-4b   # deps · checkout · GPU
$ rewardbox run robometer-4b robot.mp4 \
      --instruction "open the drawer" -o result.json
    $ rewardbox bench \
      --manifest RRM-Bench-1K/inputs/single_view.jsonl \
      --model robometer-4b --strategy fps --fps 1 \
      --no-include-last -o runs/robometer-4b
$ python RRM-Bench-1K/tools/evaluate.py \
      --predictions runs/robometer-4b/robometer-4b.json
